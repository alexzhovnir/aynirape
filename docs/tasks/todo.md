**Проект:** aynirape.com — интернет-магазин rapé / амазонского церемониального снаффа, аппликаторов (tepi & kuripe), ароматики, добавок и украшений.  
**Тип работ:** миграция с legacy-платформы (MODX) на новый стек с новым дизайном, сохранением всего контента и функционала, переносом почты и сопутствующих интеграций.  
**Домен:** остаётся прежним — `aynirape.com` (без ребрендинга).  
**Дата составления:** 2026-08-07.

## 1. Цели и результат

### 1.1. Задачи миграции

1. **Воспроизведение контента и функционала:** Полностью воспроизвести на новом сайте весь контент и функционал существующего сайта (каталог, товары, блог, статические страницы, мультиязычность, корзина/заказ, аккаунт, избранное, возрастной гейт 18+).
2. **Новый дизайн:** Реализовать новый дизайн (UI/UX) без потери данных и SEO-веса.
3. **Почта:** Перенести почту домена и настроить связанные с ней интеграции (транзакционные письма, аутентификация домена).
4. **Бесшовный переезд:** Переключить домен `aynirape.com` на новый сайт без даунтайма и без потери позиций в поиске.

### 1.2. Критерий приёмки (Definition of Done)

Новый сайт на `aynirape.com` отдаёт все прежние URL (или корректно редиректит их), проходит функциональные тесты чек-листа ([§11](#11-чек-лист-приёмки-definition-of-done)), почта работает и письма проходят аутентификацию (`SPF`/`DKIM`/`DMARC` = pass), а SEO-паритет подтверждён ([§8](#8-seo-и-редиректы-домен-тот-же)).

### 2.3. Известные проблемы AS-IS (исправить при миграции, не переносить как есть)

- URL-архитектура языков «грязная»: язык задаётся и через путь (`/it/`, `/fr/`), и через query (`?lang=xx`), иногда конфликтующе (`/it/shop/...?lang=fr`) → дубли и путаница канониклов.
- `Disallow: *?*` в `robots.txt` блокирует весь не-английский каталог (query-URL). После перехода на чистые пути языков это правило убрать.
- Sitemap содержит мусорные системные страницы (`/404`, `/403`, `/search`, `/favorites`, `/order`) — исключить из индексации.
- Шаблонный баг: попадает в индекс `/?lang=it&search={search}` (литеральный плейсхолдер).

## 7. Требования к почте и интеграциям

**Текущее размещение:** Почта на хостинге (cPanel), домен aynirape.com остаётся.  
**Объём работ (согласован с заказчиком):** перенос ящиков + транзакционные письма + SPF/DKIM/DMARC.

### 7.1. Перенос почтовых ящиков

- Инвентаризация всех ящиков на домене (напр. `info@`, `support@`, `orders@`, персональные).
- Выбор целевого решения для хранения почты: остаётся текущий cPanel-хостинг ИЛИ переезд на отдельного почтового провайдера (Google Workspace / Yandex 360 / Zoho / Migadu) — согласовать. По умолчанию: сохранить существующий почтовый хостинг, если сайт переезжает на отдельный сервер приложений (backend/frontend отделяются от почты).
- **Важно:** при смене хостинга приложения почта не должна «переехать» вместе с сайтом по ошибке — MX и почтовый сервис вынести/зафиксировать отдельно от веб-хостинга.
- Полная миграция содержимого ящиков (письма, папки, контакты) через IMAP-sync (напр. `imapsync`) без потери данных. Проверка целостности после переноса.
- Обновление DNS: MX-записи указывают на актуальный почтовый сервер; автодискавери (`autodiscover`/`autoconfig`) при необходимости.

### 7.2. Транзакционные письма (из приложения / Medusa)

- Подключить сервис отправки: Resend / Postmark / SendGrid / Amazon SES (выбрать — рекомендация: Resend или Postmark за простоту и доставляемость).
- Шаблоны писем (на 4 языках, в фирменном стиле): подтверждение заказа, статус/отгрузка, восстановление пароля, регистрация, уведомления администратору о новом заказе, контактная форма.
- Отдельный поддомен для отправки (напр. `mail.aynirape.com` / `send.aynirape.com`), чтобы не смешивать репутацию с основной корпоративной почтой.
- Интеграция с Medusa через event subscribers / notification module.

### 7.3. Аутентификация домена (SPF / DKIM / DMARC) — обязательно

- **SPF:** одна TXT-запись, включающая и почтовый хостинг (получение/отправка сотрудниками), и сервис транзакционных писем. Не превышать лимит 10 DNS-lookup.
- **DKIM:** ключи для почтового хостинга и отдельно для сервиса транзакционных писем (у каждого свой селектор).
- **DMARC:** запись `_dmarc.aynirape.com`. Старт с `p=none` + агрегированные отчёты (`rua`) → мониторинг 2–4 недели → ужесточение до `p=quarantine`/`p=reject`.
- **Проверка:** mail-tester.com / MXToolbox → цель pass по всем трём.
- **Учесть Cloudflare:** DNS домена на Cloudflare; MX/TXT/DKIM-записи проксировать нельзя (DNS-only, «серое облако»).

### 7.4. Маркетинговая рассылка (вне текущего объёма — опция)

Newsletter / брошенная корзина / подписки (Mailchimp/Klaviyo) — не входит в согласованный объём, вынесено как будущая опция. Заложить поле подписки в футере и совместимость.
